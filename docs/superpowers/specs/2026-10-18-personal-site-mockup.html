Surviving chain reorgs in yabe

Part 2 of 2 on yabe

A block explorer has one job: show the chain as the node sees it. The trouble is that the node changes its mind. When a competing branch overtakes the tip, blocks the indexer already stored stop being part of the main chain.

Finding where the chains diverge

The indexer walks back from its own tip, asking the node for the hash at each height, until the two agree. Everything above that point goes in a single DELETE, in one transaction.

// walk back until our hash matches the node's
while (stored.hash !== await node.getBlockHash(h)) {
  h -= 1;
}

Because each block is written in its own transaction, a crash at any point leaves the database consistent, and the indexer resumes where it stopped.
